# Serverless and Function Abuse - Red Team Sub-Skill

> **Cyber Monster** | Family: [`Cloud, Container and Supply Chain`](../README.md) | Tier: **leaf** | Paired Counterpart: [`cloud-detection-and-logging`](../../../blue-team/detection-and-monitoring/cloud-detection-and-logging/SKILL.md)

## Mechanism and Preconditions

Serverless review has three distinct surfaces and they fail differently. The function's own authority: its execution role, which is often broader than the function needs because it was generated by a framework or copied from a template, and which is reachable by anything that can invoke the function. The event source: an API Gateway route, an S3 notification, a queue trigger, or a public function URL, each of which is an entry point that may not appear in the application's inventory. The function's environment: `Environment.Variables` is readable by anyone with `lambda:GetFunctionConfiguration`, so a secret in an environment variable is a secret in an API response, and the role's own permissions are readable the same way. The abuse paths follow: an SSRF or injection in a function reaches the execution role's credentials from the runtime environment, and a function with a broad role and a public URL is a directly reachable privileged compute primitive. The review question is which functions are reachable from untrusted input and what their roles can do — and the answer is checkable with two API calls per function.

## Quick Start

Follow these **IF / THEN** decision rules before reading any companion file:

1. **IF** a function has a public URL or a route with no authoriser **THEN** the reachability is the finding; enumerate the role's actions next.
2. **IF** the execution role is `*` on a service or has `iam:` write actions **THEN** the function is a privileged compute primitive, and injection in it is escalation.
3. **IF** a secret is in `Environment.Variables` **THEN** anyone with `lambda:GetFunctionConfiguration` reads it; the control is a secrets manager reference.
4. **IF** the function's timeout and memory are large **THEN** it is also a resource-abuse target; note the concurrency limit.
5. **IF** the question is whether the role can reach other data **THEN** start at [`cloud-iam-privilege-escalation`](../cloud-iam-privilege-escalation/SKILL.md).
6. **IF** the function runs in a VPC with a metadata endpoint reachable **THEN** the credential path is the same as [`aws-attacks-compute-and-metadata`](../aws-attacks-compute-and-metadata/SKILL.md).
7. **IF** every reachable function has a scoped role and no plaintext secrets in its environment **THEN** record `Verified Safe` with the invocation URLs and the role names.

## Procedure

1. **Enumerate the reachable functions.** Function URLs, API Gateway routes, queue and bucket triggers, and scheduled invocations. Reachability from the internet is the first filter.
2. **Read the execution role per function.** `lambda:GetFunctionConfiguration` returns the role ARN and the environment keys, which is two facts in one call.
3. **Choose the branch.** Public invocation, over-broad role, environment-stored secret, or resource abuse.
4. **Define the baseline-vs-probe differential.** Baseline: the function's declared trigger and role, as read from the API. Probe: an unauthenticated invocation attempt, which returns `200`, `403`, or `401`. A `200` on an unauthenticated request is the finding; the role's actions are the consequence.
5. **Name the stop condition.** Stop at the first unauthenticated invocation that succeeds, or the first role with write actions on a service the function does not use. Do not invoke a function that performs side effects.
6. **State the proof.** Report the function name, its trigger, the unauthenticated response, the role's action list, and the environment keys present. If every path requires authorisation and every role is scoped, record the negative with the API output.

## Concrete Patterns

| Indicator | What it proves | Stack / surface |
|---|---|---|
| `AuthType: NONE` on a function URL | Anyone with the URL can invoke the function and use its role | Lambda function URLs |
| An API Gateway route with no authoriser | Public invocation through the gateway, which is the same exposure with a different front door | API Gateway, HTTP API |
| `"Effect": "Allow", "Action": "*", "Resource": "*"` on the execution role | The function is a privileged compute primitive reachable from its trigger | Lambda execution roles |
| `Environment.Variables` containing `DB_PASSWORD` | A plaintext secret readable through `GetFunctionConfiguration` | Lambda configuration |
| `ReservedConcurrentExecutions` unset on a public function | No concurrency cap, so the function is a cost and availability target | Lambda configuration |
| A role with `secretsmanager:GetSecretValue` limited to one ARN | Correct scoping: the function reads one secret and nothing else | Execution role policies |

## Worked Contrast

**Vulnerable: public function URL, wildcard execution role, secret in the environment**

```yaml
# SAM template
PublicApi:
  Type: AWS::Serverless::Function
  Properties:
    Handler: app.handler
    Runtime: python3.12
    FunctionUrlConfig:
      AuthType: NONE            # anyone with the URL
    Environment:
      Variables:
        DB_PASSWORD: "hunter2-prod"     # readable via GetFunctionConfiguration
    Policies:
      - AWSLambdaFullAccess             # broad managed policy
```

**Hardened: authorised invocation, scoped role, secret resolved at runtime**

```yaml
ApiFn:
  Type: AWS::Serverless::Function
  Properties:
    Handler: app.handler
    Runtime: python3.12
    FunctionUrlConfig:
      AuthType: AWS_IAM          # signed requests only
    Environment:
      Variables:
        DB_SECRET_ARN: !Ref DbSecret        # an ARN, not the value
    Policies:
      - Statement:
          - Effect: Allow
            Action: secretsmanager:GetSecretValue
            Resource: !Ref DbSecret
          - Effect: Allow
            Action: ["logs:CreateLogStream", "logs:PutLogEvents"]
            Resource: !Sub "arn:aws:logs:${AWS::Region}:${AWS::AccountId}:log-group:/aws/lambda/*"
    ReservedConcurrentExecutions: 20
```

**Why this matters:** The left function is an unauthenticated endpoint with a role that can do nearly anything, and its database password is readable from the configuration API without invoking it. The right function requires a signed request, holds only a secret ARN whose value it fetches at runtime under a single-resource grant, and caps concurrency so it is not a cost target.

## When It Is NOT This Issue

- **A public function that returns static content and whose role has no data access.** Reachability without authority; the role is the argument.
- **A secret in an environment variable that the platform encrypts and that only the function's own role can read.** Still weaker than a manager reference, but the exposure needs `GetFunctionConfiguration` on that function.
- **A wildcard action in a role used only by a function with no event source.** Not reachable; the finding would need a trigger.
- **A large timeout on a batch function with a scoped role.** Cost is bounded by the invocation source.
- **An API Gateway route with a custom authoriser.** Authorisation exists; the finding would be in the authoriser.
